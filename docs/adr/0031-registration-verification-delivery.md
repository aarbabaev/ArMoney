# ADR 0031: fenced registration verification delivery

Status: implemented source, disabled by default; local clean-slice QA and independent source review complete; published-head CI and linked acceptance pending. Not deployed or activated.

Auth owns encrypted verification intents, challenges and PostgreSQL lease fences. Add one bounded serial delivery worker behind `AUTH_VERIFICATION_DELIVERY_ENABLED`, default false. Disabled configuration constructs no worker or delivery clients and requires no delivery credentials. This minimal slice registers no verification or proof routes, adds no login-notice worker or bridge, and leaves registration, session and ACTIVE-identity authority unchanged. Existing web SSO behavior is preserved.

After claiming an unexpired lease, decrypt the stored destination/code immediately before delivery. Use the stable delivery UUID for local SMS idempotency and preserve the encrypted payload across retries. Perform network I/O outside transactions; recheck expiry before sending and acknowledge only through the current database fence. Timeout, interruption, malformed acknowledgement and dependency failure never establish verification. Delivery acknowledgement may open a challenge through the Store; the worker cannot create a receipt, projection acknowledgement or ACTIVE identity. Code-consumption support in source is not an exposed registration route.

Use only the existing Mailtrap Sandbox SMTP transport and local SMS capture protocol. SMTP requires authenticated STARTTLS, certificate/hostname validation and the fixed sandbox host. SMS uses a fixed private destination, dedicated sender credential, no redirects, bounded bodies/deadlines and strict 200/201 acknowledgements. Neither transport is activated by this change. Do not log provider replies, decrypted codes or contact values. Sandbox capture is not carrier delivery or proof of subscriber possession.

SMTP acknowledgement loss can duplicate mail; no provider exactly-once guarantee is claimed. SMS retries retain the same idempotency key and payload. Conflicts, expired tombstones, throttling and capacity errors cannot become acknowledgement or trigger automatic clearing. Finite challenge lifetime, bounded attempts and encrypted-payload cleanup remain authoritative. Shutdown stops new claims and closes owned resources; stale or interrupted workers cannot acknowledge another lease.

The clean unpublished V6 migration is byte-identical to the original dirty worktree's unpublished V7 registration-verification migration. Original V6 login-notice, V7 verification and V8 proof files remain untouched in that worktree. The bounded audit of 38 advertised heads/history found no published V6–V8, not universal absence from all clones or databases. Verify target Flyway history before any authorized migration. See the [delivery contract](../../auth-service/VERIFICATION-DELIVERY-CONTRACT.md) for the exact hash and protocol.

Historical 71/51/6/7 tests apply only to the dirty slice and do not prove this clean adaptation. The clean slice has 212 passing unit and 56 distinct passing PostgreSQL integration tests across the initial run and focused rerun after two fixture-only closure corrections. The populated V5-to-V6 upgrade preserves existing identities, sessions, contacts and migration checksums. Independent source review is clear. Required affected-component CI and disposable linked acceptance remain integration gates; no single successful full-check rerun is claimed. The missing untracked Store preimage prevents a historical byte-level minimality claim: the recorded current `61F78` full-source review and prior six PostgreSQL cases require complete adapted-source review, not assumptions about omitted proof tests.

Projection, trusted provider observations, legacy migration and enforcement on every session entry remain separate design/activation gates. No live provider send, schema application, runtime activation or deployment is authorized by this ADR. Absent verification/proof endpoints remain 404; no proof-write 503 implementation is part of this slice.
