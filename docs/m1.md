# M1 delivery and acceptance

M1 is the first functional banking milestone. Source includes auth/SSO, profiles,
operator-attested phone recipients, durable wallet provisioning and live balances,
public P2P orchestration, payment history, in-app notifications and native SwiftUI
screens. See the [contract](p2p-contract.md) and [ADR 0009](adr/0009-phone-p2p-payments.md).

Acceptance requires exact-revision green CI and independent review:

- Requester-scoped idempotency rejects changed payloads and posts retries once.
- Concurrent spending cannot overdraw; postings balance and projected balances reconcile.
- A ledger outage leaves durable PENDING intent; restart resumes it.
- A ledger commit followed by a failed payment completion transaction recovers without
  a second posting or duplicate notifications.
- Private APIs, balances, payment history and notifications enforce ownership boundaries.
- Unverified phones do not resolve; a changed recipient must be reconfirmed.
- iOS uses exact integer money and retains uncertain commands across restart/sign-out.

`scripts/p2p-smoke.py` is a disposable CI fixture with synthetic balanced funding and
fault injection, never a manual command for the persistent stack. Unit, architecture,
PostgreSQL and macOS tests complement this acceptance. Source or a health response
alone does not prove deployment, physical-iPhone behavior or milestone completion.

No SMS or push provider, top-up API, currency conversion or pagination is included.
New wallets start at zero. Operator phone attestation requires an out-of-band check.
Production identity controls, restricted database roles, observability, reconciliation
operations and further lifecycle features remain future work.
