# M1 delivery plan

The foundation and the first identity/session slice are implemented. Registration,
login, current identity and logout work through gateway. Production identity controls
and the financial slices below remain unfinished.

1. Auth and ownership: password hashing with a vetted algorithm, token lifecycle,
   service authentication, negative authorization tests, user onboarding.
2. Wallet/account creation: explicit API contracts, application ports, persistence
   adapters, schema-generated jOOQ where business queries justify code generation.
3. Ledger P2P command: atomic balance check/post, deterministic locks, idempotent
   payment ID with payload matching, immutable corrections, concurrency tests.
4. Payment orchestration: requester-scoped idempotency, durable PENDING recovery,
   reconciliation after uncertain HTTP outcomes, retry/backoff and timeouts.
5. Gateway routes, contract tests and a complete P2P acceptance scenario.

Definition of M1 done: authorized same-currency P2P changes balances exactly once;
concurrent and retried requests cannot overspend; postings balance; crash recovery
converges; CI proves this with real PostgreSQL. Bootstrap does not meet this yet.
