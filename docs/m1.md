# M1 delivery plan

Implemented: bootstrap; auth registration/login/me/logout; current-user profiles;
wallet metadata and durable ledger-account provisioning; private ledger account/balance
APIs and atomic transfer commands; optional Keycloak authorization code/PKCE exchange
and a native iOS client for SSO, profiles and wallets.

Ledger tests prove balanced postings, nonnegative customer balances, same-payment
retry, concurrent debit exhaustion, deterministic locks, rollback and restart.
The private ledger trusts authenticated service callers. It is not public P2P.

Next:
1. Payment orchestration: requester-scoped client idempotency, stable ledger payment ID,
   durable PENDING recovery, reconciliation after uncertain outcomes and bounded retries.
2. Public gateway P2P endpoints and complete acceptance scenarios. Before implementation,
   freeze payment/wallet contracts and an ADR: source ownership, recipient resolution,
   ACTIVE/READY eligibility, currency agreement and ledger-confirmed completion.
   Independently test lost responses after ledger commit, restart/reconciliation,
   payload conflicts, concurrent spending and durable rejections. Funding remains
   a separate product decision; use synthetic balanced fixtures only in disposable CI.
3. Production identity controls, restricted database roles, observability and hardening.

M1 is complete only when authorized public P2P changes balances exactly once,
concurrent/retried requests cannot overspend, entries balance, and crash recovery
converges. Ledger alone is not M1 completion.
